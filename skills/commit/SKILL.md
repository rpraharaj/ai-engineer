# Commit

Create one honest commit from what is actually in the tree. Do not push unless the user asked. Do not amend unless the user asked and the commit is yours and not on a shared remote.

If `git` is missing or this is not a repository, stop.

## Inspect

Run:

```sh
git status --short
git diff
git diff --cached
git log -8 --oneline
git rev-parse --abbrev-ref HEAD
```

If there is no diff and nothing untracked that belongs in the commit, stop: nothing to commit.

## Refuse secrets

Load `engineering-bar` (paths in that skill) and apply **Secret files**. If any match, stop and tell the user. If `AGENTS.md` exists, honor it too.

## Stage

- Stage only files that belong to the request the user is committing.
- Leave unrelated dirty files unstaged and list them.
- If the working tree mixes two unrelated changes and the user did not say "commit everything," make one commit for the requested change only. Do not silently bundle the rest.
- Do not use `git add .` unless the user asked to commit all remaining changes and the secret check passed.

## Message

Match `git log`:

- If recent commits use `type(scope): subject` or `type: subject`, use that.
- If they are plain sentences, write a plain sentence.
- Subject = what changed and why, from the diff, in the repo's language. No invented files.
- Body only if the "why" does not fit the subject (migration, follow-up, risk).

Do not mention agents, models, or "generated by."

## Create the commit

Use a non-interactive commit. Prefer a here-doc so quoting stays correct:

```sh
git commit -m "$(cat <<'EOF'
subject line

optional body
EOF
)"
```

If hooks fail, fix the cause (format, lint, test). Do not `--no-verify` unless the user explicitly asked.

## Done

Report:

- Branch
- Commit hash and subject
- Files included
- Files left unstaged
- That you did not push (unless they asked and you did)

If they also asked to open a PR, continue with `open-pr`.
